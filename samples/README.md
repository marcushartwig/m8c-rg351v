# Test samples

Ten synthesised one-shots and tones for the M8's sampler. Generated by
[`scripts/make-test-samples.py`](../scripts/make-test-samples.py) — nothing here
is sourced from anyone else, so there is nothing to license.

Mono, 44.1 kHz, 16-bit. The M8 docs recommend mono to reduce microSD load when
several sample channels play at once.

| file | length | notes |
| --- | --- | --- |
| `KICK.wav` | 0.45s | pitch sweep 115→45 Hz |
| `SNARE.wav` | 0.22s | 185 Hz tone + high-passed noise |
| `HAT_CL.wav` | 0.06s | closed hat |
| `HAT_OP.wav` | 0.34s | open hat |
| `CLAP.wav` | 0.30s | three bursts + tail |
| `SINE_C3.wav` | 1.00s | tuned reference |
| `SAW_C3.wav` | 1.00s | tuned reference |
| `SQUARE_C3.wav` | 1.00s | tuned reference |
| `TRI_C3.wav` | 1.00s | tuned reference |
| `SINE_C4.wav` | 1.00s | one octave up |

The `_C3` files are at **C3 = 130.81 Hz**, verified to within 0.07 cents. Set
that as the instrument's root note and the keyboard will track true — which also
makes it obvious immediately if the root is set wrong. All tones have 5 ms fades
so they neither click on trigger nor at a loop point.

## Getting them onto the M8

The microSD **has to come out of the Teensy**. The M8 Headless exposes only CDC
serial and USB audio — no mass storage — so nothing can write to that card over
the USB link, and m8c is a display/input client with no file transfer. Dirtywave's
own docs say the same: close the display client, unplug the Teensy, remove the
card.

1. Power down, take the microSD out of the Teensy 4.1
2. Mount it on the Mac (FAT32)
3. Copy these into `/Samples` on the card — a subdirectory such as
   `/Samples/TEST` is fine, keeping the full path under 127 characters
4. Reinsert, reconnect, relaunch m8c

Copying them to the RG351V's own SD card does nothing — the M8 never reads it.

## Regenerating

```bash
python3 scripts/make-test-samples.py [outdir]
```

Deterministic: the noise generator is seeded, so output is byte-identical
between runs.
